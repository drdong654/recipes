# CAESAR — AN INTERACTIVE COOKING EXPERIENCE
## Technical Specification · Version 2.0

### Роль

Ты — команда из Senior Frontend Engineer, Creative Developer, UI/UX Designer, Motion Designer и QA Engineer.

Твоя задача — самостоятельно спроектировать, реализовать и протестировать законченное интерактивное веб-приложение для приготовления салата «Цезарь» с курицей.

**Ключевой принцип:**

Это не обычный сайт с рецептом, не интернет-магазин и не административная панель.

Это иммерсивный цифровой кулинарный опыт, объединяющий эстетику французского гастрономического журнала и функциональность современного мобильного приложения.

**Название:** Caesar — An Interactive Cooking Experience.

**Язык интерфейса:** русский.

**Визуальные французские акценты:** допускаются только в декоративных заголовках, например:
- L'Atelier Culinaire
- Les Ingrédients
- La Préparation
- Bon Appétit

Все инструкции, кнопки, уведомления, подсказки, ошибки и элементы навигации должны быть на русском языке.

# 5. Shared Element Transition

**Это одна из ключевых функций проекта.**

При нажатии «Начать готовить» фотография блюда должна плавно переходить из большой обложки в компактную шапку режима приготовления.

Реализуй с помощью Motion for React:

- `LayoutGroup`
- `layoutId`
- `AnimatePresence`
- layout transitions

## Требования

1. Фотография на обложке крупная.
2. При переходе она визуально уменьшается.
3. Одновременно перемещается в компактную область шапки.
4. Сохраняется визуальная непрерывность.
5. Заголовок и элементы интерфейса плавно перестраиваются.
6. Не должно быть резких скачков layout.
7. Не должно быть мерцания изображения.

Используй один и тот же стабильный image asset для shared element.

Если архитектура требует временного сосуществования исходного и целевого элемента, реализуй переход корректно через Motion.

Для `prefers-reduced-motion` используй мгновенную смену состояния без масштабирования и перемещения.

# 6. Ingredients Studio

## Назначение

Интерактивный список продуктов с возможностью пересчёта порций и отметки подготовленных ингредиентов.

## UI

Кремовая панель с большими скруглениями.

Заголовок:
«Ингредиенты»

Декоративная подпись:
«Les Ingrédients»

Переключатель количества порций:
- Минимум 1
- Максимум 6
- По умолчанию 2

Каждый ингредиент содержит:
- Миниатюрную иконку или качественную иллюстрацию.
- Название.
- Количество.
- Единицу измерения.
- Индикатор готовности.

Раздели ингредиенты на:
- Для салата
- Для соуса

## Интерактивность

При нажатии на ингредиент:

1. Появляется отметка готовности.
2. Строка мягко уменьшается и исчезает из списка «Нужно подготовить».
3. Ингредиент появляется в свёрнутом разделе «Подготовлено».
4. Счётчик готовности обновляется.
5. Можно отменить отметку и вернуть продукт в основной список.

Реализуй с помощью:
- `AnimatePresence`
- `motion.div`
- стабильных ключей
- layout animations

Не удаляй ингредиенты из данных.

Используй два производных списка на основе общего состояния.

## Пересчёт порций

Количество продуктов пересчитывается автоматически.

Сохраняй исходные количества в числовом формате.

Используй типизированную модель:

`Ingredient { id, name, amount, unit, category }`

Учитывай дробные значения.

Не допускай некрасивых чисел вроде `0.333333333`.

Для небольших количеств используй понятные дроби или аккуратное округление.

## Дополнительно

- Кнопка «Скопировать список покупок».
- Индикатор подготовленных ингредиентов.
- Сохранение отметок.
- Кнопка «Перейти к приготовлению».

# 7. Cooking Mode

## Основная концепция

Режим приготовления должен быть максимально удобным для человека, у которого заняты руки.

Один главный этап на экране.

Крупные инструкции.

Минимум лишних элементов.

## Композиция

Верх:
- Компактная фотография блюда или этапа.
- Название рецепта.
- Индикатор прогресса.

Центр:
- Номер этапа.
- Название.
- Крупная фотография текущего действия.
- Подробная инструкция.
- Чек-лист.

Низ:
- Таймер.
- Кнопка «Назад».
- Кнопка «Следующий этап».

На мобильных устройствах основные кнопки должны быть доступны без неудобного дотягивания.

Используй sticky bottom action bar с учётом safe-area inset.

## Этапы

### Этап 1. Подготовка

- Промыть романо.
- Тщательно обсушить листья.
- Подготовить остальные продукты.
- Разогреть духовку.

### Этап 2. Курица

- Приправить куриное филе.
- Обжарить на среднем огне.
- Проверить внутреннюю температуру не менее 74 °C.
- Дать мясу отдохнуть.
- Нарезать ломтиками.

### Этап 3. Крутоны

- Нарезать белый хлеб.
- Добавить оливковое масло.
- Запечь при 180 °C до золотистого цвета.
- Остудить.

### Этап 4. Соус

- Подготовить чеснок и анчоусы.
- Смешать с майонезом, горчицей и лимонным соком.
- Добавить пармезан.
- Довести до нужной консистенции.

### Этап 5. Сборка

- Соединить романо с частью соуса.
- Добавить курицу.
- Добавить сухарики.
- Украсить пармезаном.
- Подать сразу.

Для каждого этапа создай отдельные подробные инструкции и полезные подсказки.

# 8. Persistent Cooking Timers

**Критически важная функциональность.**

Таймеры не должны сбрасываться при переключении этапов.

## Архитектура

Создай отдельный TimerManager.

Таймеры должны храниться независимо от текущего экрана.

Каждый таймер имеет:
- id
- label
- duration
- status
- targetEndTime
- remainingMs

## Поведение

Пользователь запускает таймер курицы.

Затем переходит к этапу крутонов.

Таймер курицы продолжает отсчёт.

Пользователь может запустить второй таймер.

Оба таймера работают независимо.

При возвращении к курице оставшееся время отображается корректно.

## Технические требования

Не используй простой декремент счётчика как единственный источник истины.

Используй `Date.now()` и timestamp завершения.

Сохраняй состояние в localStorage.

После обновления страницы восстанавливай таймеры и пересчитывай оставшееся время.

Поддержи:
- Start
- Pause
- Resume
- Reset
- Completion

При завершении:
- Визуальное уведомление.
- Ненавязчивый звуковой сигнал после разрешённого пользовательского взаимодействия.
- Доступная текстовая индикация.

Не обещай надёжные системные уведомления или работу звука в фоне без соответствующих браузерных разрешений.

Для мобильных браузеров предусмотрите, что JavaScript может приостанавливаться в фоне. При возвращении таймер должен корректно восстановиться по timestamp.

Например:

`caesar-experience:v1`

Добавь безопасную обработку повреждённых или устаревших данных.

При повторном посещении, если готовка не завершена, предложи:
